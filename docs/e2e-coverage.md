# Product verification coverage

## Accounts and keys

`accounts-page.spec.ts` and `accounts/security.spec.ts` exercise the shared UI against a real relay, PostgreSQL and isolated controlled native children. They cover encrypted API enrollment, two retained subscription identities, CRUD/default persistence, navigation/filter preservation, offline metadata, untrusted recipient refusal and logout during native verification. They do not authenticate real provider accounts.

`tests/extension-e2e/accounts.spec.ts` exercises browser encryption in the production MV3 artifact through a real Native Messaging bridge and approved local grant. It checks readiness and absence of the plaintext key from Chrome storage and returned profile metadata. The fixture records CSP violations and page errors; it never registers the extension in a personal browser profile.

The browser suite runs Chromium with an iPhone 13 viewport against the real Vite application, NestJS relay, PostgreSQL, signed synthetic Telegram identities, and real WebSockets. It never sends Telegram messages or operates personal chats. A mobile viewport is not physical Telegram acceptance.

`tests/e2e/support/relay-fixture.ts` represents a controlled device. Its commands are acknowledged without running an external application. `tests/e2e/product/` controls that device and network faults entirely inside the test process. No application debug endpoint or authentication bypass is used. Capability fixtures describe advertised capabilities; they do not establish native integration compatibility.

Run the browser suite with `npm run test:e2e`. PostgreSQL must be available through `TEST_DATABASE_URL` or the test Compose default. Playwright owns ports 4173 and 3000. If another project uses 4173, run `E2E_APP_PORT=4174 npm run test:e2e`; the frontend URL and relay origins change together. Do not run two browser suites simultaneously.

## Interpretation limits

A browser test that applies a source snapshot establishes rendering and command gating for that snapshot. It does not establish that the real native adapter generated it. Controlled-device permission tests explicitly publish removal snapshots; the daemon permission tests and Codex runtime tests cover native cleanup separately.

Revoke tests cover disappearance of visible owner data; `revoke-repair.spec.ts` additionally checks draft and uncertain-command cleanup when a replacement device reuses a session identity. Native Desktop Chat/Code sending, live cmux input, physical Telegram UX, public hosting, installer trust, and real notification delivery require the external probes above. No browser pass removes those acceptance requirements.

## Reading position, native restart and long project paths

- `reading-position.spec.ts` verifies the same visible message and pixel offset after navigation, newly arriving messages and a Mini App reload; live appends preserve that reading line. Explicit scroll-to-bottom still works.
- `native-input-help.spec.ts` verifies one-click native restart, disabled duplicate actions and input availability after the authoritative binding changes. `native-restart-handoff.test.ts` covers restored sessions without a live input binding, original remote identity, fresh generation and idempotent replay. Native OS stop checks use only a disposable synthetic child in `native-process-restart.test.ts`.
- `project-dropdown.spec.ts` verifies long unbroken paths fit inside both 320 px and 390 px viewports, wrap within their menu item and remain selectable. Storybook includes `LongProjectPath`.
- Reading bookmarks contain only device/session scope, message ID and row offset, bounded to 100 entries. Browser storage failure retains an in-memory fallback. No message body or attachment path is persisted in a bookmark.

## Restart context and keyboard regression coverage

Account-management acceptance on 2026-10-18: all 174 mobile scenarios and 10 built Chrome/native scenarios passed. `accounts/recovery.spec.ts` loses committed create/enrollment replies and reloads before recovery; `accounts-page.spec.ts` reconnects the Mac without leaving Accounts. Separate unit tests cover immediate local logout/disconnect cancellation, native cleanup barriers, obsolete sign-ins and maximum-size paged metadata. Controlled peers prove transport behavior; real provider sign-in, profile-aware launch and automatic fallback remain separate release gates.

- `prompt-queue.spec.ts`, `delivery-recovery.spec.ts` and `attachments/recovery.spec.ts`: editable input during work, Enter enqueue, FIFO across native idle transitions, cancellation, exact command/attachment IDs, GET-only reconciliation, independent controls and immutable submitted attachments.
- `native-restart-ambiguity.spec.ts`: duplicate native writers produce an accurate RU/EN explanation; restart remains unavailable until a unique verified process remains. No user process is stopped by tests.
- `session-changes.spec.ts`: owned native patch expansion, syntax highlighting, literal HTML safety and mobile overflow in both languages.
- `scroll-boundaries.spec.ts`: actual bottom selects the final marker for short/blank messages; being near the bottom still follows the reading anchor. `virtualization.spec.ts` preserves the same rule through bounded history changes.

- `composer-keyboard.spec.ts`: Enter sends exactly once, Shift+Enter preserves a newline, IME composition and held Enter do not submit.
- `native-input-help.spec.ts`: no history request after a same-session restart; all 90 sampled frames preserve the message's screen coordinate while the native source changes into a cmux binding.
- `restart-context.test.ts`, `claude-restart.test.ts`, `restore-launch.test.ts`: original flags/environment, no replayed initial prompt, verified host before stop, private one-use payload. `native-restart-handoff.test.ts` covers both PTY and cmux bindings.
- `process-context.test.ts`: macOS helper reads exact argv/environment from a disposable owned process. `cmux-launch.test.ts`: exact UUID targeting, no focused fallback, denied access fails before stop.
- `artifacts/cmux-restart-acceptance.json`: actual installed cmux resumes a disposable local C fixture in the same surface/workspace with a quoted model argument, explicit bypass flag and multiline environment marker preserved. No model request or user conversation is used.
