# Оценка разработки с AI

Обновлено 2026-10-16. Единая актуальная оценка для [основного плана имплементации](superpowers/plans/2026-10-16-claude-remote-implementation.md) и спецификаций этого проекта.

**Полный пилот: 32–52 часа активной работы одного разработчика с AI.** Календарный ориентир: **4–7 дней при 8 часах активной работы в день**, без внешнего ожидания. Это плановый бюджет до первого измеренного прогона, не обещание срока и не результат benchmark.

## Из чего состоит бюджет

| Работа                  | Часы      | Состав                                                                            |
| ----------------------- | --------- | --------------------------------------------------------------------------------- |
| Выбор/проверка upstream | 2–4       | Pinned MIT-модули, происхождение, compatibility/smoke; source review уже выполнен |
| Платформа               | 6–10      | Probe 2–3; auth/ownership 2–4; pairing/connections 2–3                            |
| Адаптеры                | 8–13      | Контракты 1–2; CLI/PTY 2–3; Desktop Chat/Code 4–7; lifecycle/setup 1              |
| Наблюдение              | 6–9       | Monitor 2–3; relay/notifications 2–3; адаптация Mini App 2–3                      |
| Управление и приёмка    | 6–8       | Command/permission routing 2–3; общая приёмка и дефекты 4–5                       |
| Общий резерв            | 4–8       | Несовместимость upstream, интеграционные дефекты, упаковка/окружение              |
| **Всего**               | **32–52** | Задачи 26–40 + upstream 2–4 + резерв 4–8                                          |

## Предположения

1. AI выполняет основную генерацию, адаптацию кода и тестов; разработчик принимает решения и проверяет реальное поведение. Стек/инструменты уже доступны.
2. Переиспользуем подходящие модули вместо самостоятельного написания каждой подсистемы: собственный React UI, hooks/PTY по подходам CCGram, cmux-клиент cmux-tui с конкретными pins/исключениями из основного плана.
3. Telegram credentials, один тестовый relay, Mac и два тестовых пользователя доступны для проверки; ожидание их предоставления считается отдельно.
4. Desktop Chat Accessibility даёт доступ к выбранному чату. Это проверяется в начале; отрицательный результат требует нового способа подключения и оценки.
5. Объём пилота сохраняется: несколько изолированных пользователей, Desktop Chat/Code, обычный CLI, cmux, prompts/interrupt/permissions по capabilities, reconnect и приёмка.

## Что входит во время задач

Генерация и адаптация кода, чтение необходимых участков upstream, целевые regression tests, typecheck/build, локальный debug и документация. В приёмку входят два пользователя, negative ownership cases, реальные Desktop/CLI проверки, Telegram iOS/Android и 30-минутный нагрузочный прогон. Эти проверки не вынесены в неоплаченный по времени «потом» и не удалены ради уменьшения цифры.

Резерв учитывается один раз на весь проект. Оценка не предполагает запущенных параллельно субагентов и не считает их потенциальное ускорение уже полученным.

## Ранние проверяемые результаты

| Точка                | Бюджет                      | Что подтверждает                                                                                           |
| -------------------- | --------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Upstream smoke check | 2–4 часа                    | MIT modules/pins проверены; понятны control transport и необходимые изменения                              |
| Первый сквозной демо | 4–8 часов суммарно с начала | Изолированный upstream smoke: одна CLI-сессия и телефон; это не готовый собственный multi-user backend     |
| Полный пилот         | 32–52 часа суммарно         | Все заявленные источники и isolation/failure acceptance проходят либо конкретный blocker явно зафиксирован |

Эти точки входят в общий бюджет, не суммируются сверху. Если Desktop Chat blocker не разрешён, весь заявленный объём не считается выполненным.

## Пересмотр по факту

После первых 2–4 часов записать фактическое время, выбранный upstream, успешные операции и конкретные несовместимости. Пересчитать только затронутые задачи. Условия провала Desktop AX, лицензия/transport upstream и недоступность оборудования не скрываются добавлением произвольных недель к каждому пункту.

Старые оценки в рабочих днях заменены этой моделью: задачи оцениваются в часах работы с AI и reuse, ручная приёмка и общий резерв видны отдельно.

## Фактический статус реализации

Сгенерирован и проверен локальный стек приложения; актуальные результаты в [приёмке](acceptance.md). Историческая оценка выше не является потраченным временем. Desktop real-app и внешние Telegram/production checks остаются открытыми, поэтому всю оценку нельзя пометить как завершённую.
