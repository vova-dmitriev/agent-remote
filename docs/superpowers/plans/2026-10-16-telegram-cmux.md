# Telegram Remote — план многопользовательского сервиса

**Подтверждено:** несколько пользователей; подключение Claude Desktop **Chat и Code**, Claude Code в обычном терминале и cmux. Каждый пользователь видит и контролирует только свои устройства и выбранные сессии. **cmux необязателен.**

**Основной план:** [Claude Remote Implementation Plan](2026-10-16-claude-remote-implementation.md) — 13 последовательных задач с файлами, контрактами, тестами и pinned MIT reuse.

**Статус:** план подготовлен, реализация не начата. По исходной общей ссылке доступен один ответ ассистента; новые требования подтверждены в этой переписке.

Спецификации: [общая архитектура](../specs/2026-10-16-telegram-cmux-design.md), [источники и способы подключения](../specs/2026-10-16-claude-connectors-design.md).

## Архитектура

`Telegram Mini App → NestJS relay + PostgreSQL ← исходящий WSS ← companion на каждом Mac → адаптер Chat / Desktop Code / CLI / cmux`.

Одна привязка Mac к аккаунту, затем локальный выбор источников. Сервер проверяет ownership на всех маршрутах; companion проверяет конкретный connector, generation и capability перед действием. Устанавливать cmux для Desktop/обычного CLI не нужно.

## Подключение источников

| Источник                        | Способ подключения                                                                                                   | Существенное ограничение                                                                                    |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Claude Desktop Chat             | Локальный мастер выбора чата + подписанный Accessibility helper                                                      | AX read/send выбранного чата сначала проверяются на реальной версии; unlocked Mac, неполная видимая история |
| Claude Desktop Code             | Hooks/JSONL для событий, отдельная проверенная привязка Code UI для промптов                                         | Подтверждения только через доступный permission transport; смежный Chat не получает Code capabilities       |
| Claude Code в обычном терминале | Одна установка hooks; полный control через `remote claude` / `remote claude --resume <session-id>` в управляемом PTY | Уже запущенный чужой TTY нельзя объявлять захваченным; hooks-only mode честно показывает ограничения        |
| Claude Code в cmux              | cmux adapter + hooks/JSONL                                                                                           | Проверяются конкретные UUID и актуальная привязка; optional cmux bridge                                     |

`remote claude` — предлагаемая команда companion, не встроенная команда Anthropic. Channels рассматриваются как дополнительный transport с учётом preview/allowlist. Native Remote Control ведёт в клиенты Claude; не используется как недокументированный API Telegram. MCP сам по себе не даёт управления обычным существующим Desktop Chat.

## Порядок реализации

| План                                                                                  | Проверяемый результат                                                             | Активная работа с AI |
| ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- | -------------------- |
| [01 — Пользователи и устройства](2026-10-16-claude-remote-implementation.md#platform) | Probe всех источников, Telegram auth, ownership, pairing и revoke                 | 6–10 часов           |
| [Интеграции источников](2026-10-16-claude-remote-implementation.md#adapters)          | SessionAdapter, обычный CLI/PTY, Desktop Chat/Code helper, capability diagnostics | 8–13 часов           |
| [02 — Наблюдение](2026-10-16-claude-remote-implementation.md#monitoring)              | Общий monitor, изолированные live/history/replay, Mini App, уведомления           | 6–9 часов            |
| [03 — Управление и приёмка](2026-10-16-claude-remote-implementation.md#controls)      | Source-aware prompts/interrupt/permissions, cross-user tests, нагрузка и runbook  | 6–8 часов            |

**Разработка с AI: 26–40 часов по задачам + 2–4 часа на проверку/выбор upstream + 4–8 часов общего резерва = 32–52 часа активной работы.** Плановый календарный ориентир — **4–7 дней при 8 часах активной работы в день**, без ожидания доступов/аккаунтов/оборудования. Это первоначальный бюджет до измерения темпа исполнения.

Первый сквозной демо на готовом решении: **4–8 часов** с одной CLI-сессией и телефоном. Это промежуточная точка внутри общего бюджета, а не приёмка всего многопользовательского сервиса. Весь заявленный объём Chat/Code/CLI/cmux и проверки изоляции остаётся в плане.

Оценка Desktop Chat условна до реального AX probe: если read/send выбранного чата недоступны, способ интеграции и бюджет пересматриваются по результату проверки. Read-only/MCP bridge не считается полной поддержкой управления Chat. Ручные проверки, 30-минутный нагрузочный прогон и контроль доступа включены в бюджет. Подробности: [оценка работ](../../delivery-estimate.md).

## Границы пилота и приёмка

1. Один личный аккаунт на Telegram ID, один Mac/user, до 10 sessions/device; начальная нагрузочная цель 20 simultaneous users — предложенные квоты пилота.
2. Chat, Code, CLI и cmux показаны с отдельными capabilities. Неподдерживаемые операции запрещены и на relay, и локально; отсутствующие cmux/Accessibility не ломают остальные источники.
3. Проверяются два пользователя, одинаковые session titles, разные источники, duplicate command, late permission, child exit, смена чата/account, local draft, lock/unlock и потеря сети.
4. Desktop Chat принимает промпт в исходный выбранный чат; новый API-диалог не подменяет его. Приватные tokens/cookies и глобальный ввод в активное окно не используются.
5. Общий relay видит опубликованный текст; это объясняется при подключении. TTL/dedup, ограниченная ретенция и owner-scoped notifications остаются обязательными.
